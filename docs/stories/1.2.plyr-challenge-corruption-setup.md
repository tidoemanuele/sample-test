## Dev Notes
### Project Architecture Analysis (Complete)
**Plyr Component Structure** (38 JS files analyzed):

**Core Architecture**:
- **Main Player** (`plyr.js`): Central class constructor, initialization, configuration management
- **Event System** (`listeners.js`): Keyboard/mouse event handling, focus management
- **Controls Engine** (`controls.js`): Massive 53KB file handling all UI controls and interactions
- **Media Layer** (`media.js`): Provider setup (HTML5, YouTube, Vimeo)
- **HTML5 Handler** (`html5.js`): Native video/audio element management
- **UI Manager** (`ui.js`): DOM element creation and UI state management

**Supporting Systems**:
- **Captions** (`captions.js`): Subtitle/VTT handling (13KB)
- **Fullscreen** (`fullscreen.js`): Fullscreen API management
- **Storage** (`storage.js`): LocalStorage for user preferences
- **Source** (`source.js`): Media source switching and quality selection

**Configuration & Utils**:
- **Config** (`config/`): defaults.js, states.js, types.js - Configuration management
- **Utilities** (`utils/`): 20+ utility modules (elements, events, strings, etc.)
- **Plugins** (`plugins/`): YouTube, Vimeo, Ads, Preview thumbnails

**Critical Integration Points**:
1. **Event Flow**: listeners.js → controls.js → media playback
2. **Initialization Chain**: plyr.js → media.js → html5.js → controls.js
3. **State Management**: Configuration object passed through all components
4. **DOM Manipulation**: ui.js creates elements, controls.js binds events
5. **Build Pipeline**: Gulp compiles ES6 modules + Sass → UMD/ESM outputs

**Architecture Complexity Indicators**:
- Circular dependencies (captions ↔ controls)
- Large monolithic files (controls.js = 53KB)
- Deep module interdependencies
- Multiple provider abstraction layers
- Complex event delegation patterns

### Corruption Strategy Design (Detailed)
**Realistic Corruption Scenarios** (Based on Architecture Analysis):

**🎯 Corruption 1: Play/Pause Button Event Binding Issue**
- **File**: `src/js/controls.js` (line ~57-58)
- **Issue**: Play button selectors misconfigured during controls setup
- **Symptom**: Play/pause buttons render but don't respond to clicks
- **Root Cause**: Incorrect element selector in `this.config.selectors.buttons.play`
- **Learning Goal**: Understanding event delegation and selector specificity in large projects
- **AI Debugging**: Requires architectural understanding of controls → buttons → event flow

**🎯 Corruption 2: Media Initialization Race Condition**
- **File**: `src/js/plyr.js` (line ~314 autoplay logic)
- **Issue**: Autoplay attempts before media is ready
- **Symptom**: Player shows loading state indefinitely, no error messages
- **Root Cause**: Missing event listener registration before autoplay trigger
- **Learning Goal**: Understanding asynchronous initialization patterns
- **AI Debugging**: Requires understanding component lifecycle and event timing

**🎯 Corruption 3: Volume Control State Sync Issue**
- **File**: `src/js/controls.js` (volume input handling)
- **Issue**: Volume slider moves but doesn't update actual media volume
- **Symptom**: Visual feedback works, audio doesn't change
- **Root Cause**: Missing connection between input change event and media.volume property
- **Learning Goal**: Understanding state synchronization between UI and media APIs
- **AI Debugging**: Requires understanding UI → state → media pipeline

**🎯 Corruption 4: Configuration Object Reference Error**
- **File**: `src/js/ui.js` or `src/js/controls.js`
- **Issue**: Deep object property access without null checking
- **Symptom**: Player fails to initialize with generic "Cannot read property" error
- **Root Cause**: Configuration object structure assumed incorrectly
- **Learning Goal**: Understanding configuration management in large applications
- **AI Debugging**: Requires understanding object structure and defensive programming

**🎯 Corruption 5: CSS Build Pipeline Issue**
- **File**: `src/sass/plyr.scss` or related
- **Issue**: Critical CSS class not compiled or scoped incorrectly
- **Symptom**: Player initializes but controls are invisible/incorrectly styled
- **Root Cause**: Build system not processing specific SCSS correctly
- **Learning Goal**: Understanding build systems and asset compilation
- **AI Debugging**: Requires understanding build pipeline and CSS scoping

**Corruption Implementation Principles**:
- Maintain syntactic correctness (no obvious compile errors)
- Create issues requiring systematic debugging approach
- Ensure fixes need architectural understanding, not just syntax fixes
- Mirror real-world production debugging scenarios
- Enable effective AI-assisted investigation
