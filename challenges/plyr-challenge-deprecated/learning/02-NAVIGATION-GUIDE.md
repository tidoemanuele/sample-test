# Plyr Project Navigation Guide

## 🗺️ Understanding Enterprise Project Structure

This guide helps you navigate Plyr's complex architecture systematically. Use it to understand **where to look** and **why** components are organized this way.

## 📁 High-Level Directory Structure

```
plyr-challenge/
├── src/                    # Source code (your debugging target)
├── dist/                   # Compiled output (generated by build)
├── demo/                   # Example implementations
├── tasks/                  # Build system utilities
├── .github/                # Repository configuration
├── gulpfile.js            # Build system entry point
├── package.json           # Dependencies and scripts
└── README.md              # Original project documentation
```

## 🎯 Core Source Code Organization (`src/`)

### JavaScript Architecture (`src/js/`)

**🏛️ Foundation Layer**
```
plyr.js                 # Main player class (31KB)
├── Constructor & initialization
├── Public API methods (play, pause, volume)
├── Event system setup
└── Component orchestration
```

```
controls.js             # UI controls engine (53KB!)

├── Settings menus and accessibility
├── Control layout and responsiveness

listeners.js            # Event coordination (24KB)
├── Keyboard shortcuts and focus management
├── Mouse/touch event delegation
```

**🎨 Presentation Layer**

## 🔄 Critical Integration Points

Understanding these connections is key to effective debugging:

### 1. Initialization Chain
```
plyr.js constructor
└── media.js setup (provider detection)
    └── html5.js/youtube.js/vimeo.js (provider-specific)
        └── controls.js setup (UI creation)
            └── listeners.js bind (event connections)
                └── ui.js updates (visual feedback)
```

### 2. Event Flow Architecture
```
User Action (click/key)
└── listeners.js delegation
    └── controls.js handler
        └── plyr.js API method
            └── media element action
                └── ui.js visual update
```

### 3. Configuration Cascade
```
defaults.js base config
└── merged with user options
    └── passed to all components
        └── accessed via this.config.*
```

### 4. Build System Flow
```
gulpfile.js orchestration
├── JavaScript: ES6 modules → Rollup → UMD/ESM
├── CSS: SCSS → Sass → Autoprefixed CSS
├── Assets: SVG → sprite compilation
└── Output: dist/ folder generation
```

## 🎯 Debugging Investigation Strategies

### When Controls Don't Work
**Look Here First:**
1. `src/js/controls.js` (lines 50-80) - Button element detection
2. `src/js/listeners.js` (lines 500-600) - Event binding
3. Configuration object structure in browser dev tools

### When Player Won't Initialize
**Investigation Order:**
1. `src/js/plyr.js` constructor - Check for thrown errors
2. `src/js/media.js` setup - Provider detection logic
3. Console errors for missing dependencies/elements

### When Styles Are Broken
**CSS Debugging Path:**
1. `dist/plyr.css` - Check if file was generated
2. `src/sass/components/control.scss` - Control visibility
3. Browser dev tools - Inspect applied/overridden styles

### When Volume Doesn't Work
**Event Chain Analysis:**
1. `src/js/listeners.js` (volume input binding)
2. Connection to `player.volume` property
3. Media element `volumechange` event handling

## 🧭 Navigation Tips for Large Codebases

### Finding Functionality
```bash
# Search for specific functionality
grep -r "play" src/js/          # Find play-related code
grep -r "volume" src/js/        # Find volume handling
grep -r "controls" src/sass/    # Find control styling
```

### Understanding Dependencies
```bash
# See component imports
head -20 src/js/plyr.js         # Main imports
head -10 src/js/controls.js     # Control dependencies
```

### Following Event Flows
1. Start with user action (button click)
2. Find event binding in `listeners.js`
3. Follow handler to `controls.js` or main API
4. Trace through to media element interaction
5. Look for UI feedback in `ui.js`

### Configuration Debugging
1. Check `src/js/config/defaults.js` for expected structure
2. Use browser console to inspect `player.config` object
3. Compare with actual values being accessed

## 🚨 Common Architectural Pitfalls

### Circular Dependencies
- `captions.js ↔ controls.js` - Expected and handled
- Imports are carefully managed to avoid issues

### Event Timing Issues
- Components initialized in specific order
- Event listeners attached after DOM elements exist
- Async operations properly chained

### Configuration Object Depth
- Deep nesting: `this.config.selectors.buttons.play`
- Defensive access needed: check existence before use
- Type assumptions: strings vs. numbers vs. booleans

### Build System Complexity
- Multiple output targets (UMD, ESM, minified)
- Asset pipeline dependencies (CSS, SVG, JS)
- Development vs. production builds
